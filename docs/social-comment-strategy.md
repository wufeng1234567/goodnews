# 社媒评论全量采集方案

## 结论先行

评论“总数”是平台展示值，不等于平台愿意通过网页/API 返回全部明细。三个平台的真实约束不同：

| 平台 | 公开 API | 登录态 | 分页机制 | 完整评论可行性 |
|---|---|---|---|---|
| Bilibili | 有公开 Web API | `SESSDATA` 可提升主评论可见量 | 主评论 `pn/ps`；楼中楼 `/x/v2/reply/reply` 的 `root/pn/ps` | 最高；已实现分页与楼中楼完整抓取 |
| 抖音 | 无公开评论 API | 需要浏览器 Cookie/登录态 | 页面 XHR `comment/list` 的 `cursor`，签名参数 `a_bogus` | 只能浏览器滚动采集；改动 cursor/count 的直接重放不可靠 |
| 小红书 | 无公开评论 API | 必须 `web_session` 登录态 | 页面 XHR + `x-s`/`xsec_token` 签名 | 登录后浏览器滚动；容易触发安全风控 |

## 实测记录（2026-11-11）

- Bilibili `BV1MN4y177PB`：平台显示 **68,898** 条；登录态下用 `x/v2/reply` 能返回 **59 条主评论**（`max_comments=300` 单次测试），证明登录 Cookie 能突破匿名接口的 3 条限制；楼中楼接口 `/x/v2/reply/reply` 实测单个 root 可取 **151** 条回复。
- 抖音 `7690992782325240232`：详情/评论页可用；首个 `comment/list` 响应 `total=247,845`、`cursor=5`、每页 5 条。尝试把签名 URL 的 `count` 改为 20/50、`cursor` 改为 5/10 重放，服务端返回 `status_code=0` 但 `comments=[]`，说明签名/风控与原始请求绑定，不能靠改 URL 翻页。
- 小红书 `6a81d8ce...`：带 `xsec_token` 仍返回 `300012/安全限制`；保存的访客 `web_session` 不等同于登录态，采集被拒后系统自动标记为 `expired`。

## 技术路线对比

1. **官方开放 API**：只有 Bilibili 有可直接使用的公开评论 API；抖音/小红书没有面向普通开发者的公开评论接口，企业开放平台需要资质和审批。
2. **直接 HTTP 调用网页 API**：Bilibili 可行；抖音需要 `a_bogus`，小红书需要 `x-s`/`xsec_token`，签名算法随版本变化，直接硬编码不可维护；不采用。
3. **浏览器网络捕获（当前实现）**：Playwright 打开登录态页面，读取页面自己发出的评论 XHR；抖音、小红书可行，但必须用页面滚动/点击触发下一页。优点是使用真实浏览器签名与 Cookie，不伪造请求；缺点是慢、受页面结构影响。
4. **DOM 解析**：仅作为兜底，数据不稳定，容易漏字段，不作为主路径。
5. **第三方数据服务**：可以买全量，但需要 API key、费用和合规审查，当前 MVP 不引入。
6. **官方企业接口/数据合作**：如果要做生产级“全量”，这是唯一能承诺数量与稳定性的长期方案，需要平台资质，不能靠前端绕过。

## 当前实现

- 快速预览：只取少量主评论和回复，保证页面轻量。
- 评论区折叠：每条父评论最多展示 3 条子回复；超过 3 条显示“查看更多回复”，打开固定高度弹窗展示父评论和完整子回复。
- Bilibili 弹窗按需调用 `/api/v1/social/comments/replies`，对单个 root 继续翻 `/x/v2/reply/reply`，不受快速预览 5 条限制。
- 全量任务：`POST /api/v1/social/jobs` 后台运行，最多 `SOCIAL_FULL_MAX_COMMENTS`（默认 50,000）条，任务保存到 `social_fetch_jobs` + `social_fetch_records`。
- 导出：`GET /api/v1/social/jobs/{id}/export?format=xlsx|md|txt`。

## 诚实边界

- “平台显示 68,898 条”不代表能拿到 68,898 条；平台可能只开放热门主评论、折叠评论、楼中楼或被风控截断。
- 抖音/小红书全量任务是浏览器滚动采集，实际数量取决于登录态、页面是否继续返回新评论、IP 风控和平台限流。
- 当前后台任务运行在 FastAPI 进程内，服务重启会中断；生产级应迁移到独立队列（Celery/RQ/任务服务）+ 对象存储/分批导出。
